# Как опубликовать Glory IOS на GitHub Pages и подключить Mini App

Для инструкции достаточно GitHub: он хранит файлы, автоматически собирает сайт и публикует его через **GitHub Pages**. Netlify подключать не нужно. Настройки для такой публикации уже находятся в проекте.

Сейчас подготовлены локальные файлы. Репозиторий, успешная публикация и публичный адрес появятся после выполнения следующих шагов. Адрес репозитория вида `github.com/…` и адрес готового сайта вида `…github.io/…` — разные ссылки; боту нужен адрес готового сайта.

## 1. Выберите папку инструкции

У вас три отдельных проекта:

- `C:\Users\pc\Desktop\Glory-Guide` — инструкция для Telegram Mini App; публикуем эту папку.
- `C:\Users\pc\Desktop\Glory-Bot` — код Telegram-бота.
- `C:\Users\pc\Desktop\Glory-Store` — задание и будущий сайт магазина.

Для инструкции создайте отдельный репозиторий, например `glory-guide`. Папки бота и магазина в него добавлять не нужно.

## 2. Загрузите файлы через GitHub Desktop

1. Установите [GitHub Desktop](https://desktop.github.com/) и войдите в свой аккаунт GitHub.
2. Выберите **File → Add local repository**, затем папку `C:\Users\pc\Desktop\Glory-Guide`.
3. Если приложение сообщает, что в папке ещё нет Git-репозитория, нажмите **create a repository here**. Проверьте итоговый путь: он должен быть именно `C:\Users\pc\Desktop\Glory-Guide`, без второй папки Glory-Guide внутри. Если нужно указать имя и родительскую папку отдельно, используйте имя `Glory-Guide` и родительскую папку `C:\Users\pc\Desktop`. Существующие README, `.gitignore` и другие файлы сохраняйте.
4. Проверьте, что текущая ветка называется **main**. Именно её публикует подготовленная настройка. Если имя другое, переименуйте ветку через **Branch → Rename** в `main`.
5. В разделе **Changes** проверьте список. В нём должны быть исходники `src`, папка `public` с медиа, `.github/workflows/deploy-pages.yml`, `package.json`, `package-lock.json` и остальные настройки проекта. Если есть несохранённые изменения, в поле **Summary** напишите `Подготовить инструкцию Telegram Mini App` и нажмите **Commit to main**. Если создание репозитория уже сохранило все файлы и список пуст, дополнительное сохранение не требуется.
6. Нажмите **Publish repository**. Назовите репозиторий `glory-guide`. Для бесплатной публикации Pages на тарифе GitHub Free **снимите галочку Keep this code private**: репозиторий должен быть Public. Его исходники будут видны всем. Pages для приватных репозиториев доступны на подходящих платных тарифах GitHub.
7. Подтвердите **Publish repository** и дождитесь окончания загрузки.

В проекте уже есть `.gitignore`: он исключает `node_modules`, `.next`, `.netlify`, `out`, `artifacts`, журналы, `.env` и временные файлы. `.env.example` содержит безопасный образец и может быть опубликован. Токен бота, файлы сертификатов и персональные данные для работы этой инструкции не нужны; их в репозиторий инструкции не добавляйте.

Не переносите файлы из `out` в корень проекта и не загружайте зависимости вручную. GitHub сам установит зависимости и соберёт готовый сайт из исходников.

## 3. Включите GitHub Pages

1. В GitHub Desktop выберите **Repository → View on GitHub**. Откроется ваш репозиторий в браузере.
2. Перейдите в **Settings → Pages**.
3. В разделе **Build and deployment** выберите **Source → GitHub Actions**.
4. Новый workflow создавать не нужно: файл `.github/workflows/deploy-pages.yml` уже загружен вместе с проектом.
5. Откройте вкладку **Actions** и найдите **Publish Glory Guide to GitHub Pages**.
6. Если публикация ещё не началась или первая попытка завершилась ошибкой до включения Pages, откройте этот workflow и нажмите **Run workflow**, выберите ветку **main** и подтвердите **Run workflow**.
7. Дождитесь зелёной отметки. Должны успешно завершиться обе части: **build** и **deploy**. Обычно это занимает несколько минут.
8. Вернитесь в **Settings → Pages** и откройте адрес через **Visit site**. Это реальный публичный адрес вашей инструкции.

При каждом обновлении ветки `main` GitHub проверяет код, собирает статический сайт в `out` и публикует его. HTTPS-адрес сайта и путь репозитория подставляются автоматически из настроек Pages. Вводить переменные окружения или подключать отдельный сервер для обычной публикации не нужно.

Для репозитория `glory-guide` обычный адрес главной страницы выглядит так:

```text
https://ВАШ-ЛОГИН.github.io/glory-guide/
```

К скопированному адресу главной страницы добавьте `guide/`, чтобы кнопка открывала сразу первый шаг:

```text
https://ВАШ-ЛОГИН.github.io/glory-guide/guide/
```

`ВАШ-ЛОГИН` — пример, его нужно заменить своим логином. Ориентируйтесь на адрес из **Settings → Pages**, особенно если репозиторий называется иначе или подключён собственный домен.

Откройте эту ссылку на iPhone в браузере. Проверьте переходы по шагам, иллюстрации и видео. Обновление страницы на любом шаге должно сохранять выбранный шаг. Если появляется ошибка 404, сначала убедитесь, что **deploy** завершился успешно, а ссылка содержит имя репозитория и `/guide/`.

## 4. Подключите кнопку «Инструкция» в боте

В локальной папке Glory-Bot подготовлены изменения в `app_handlers.py`, `keyboards.py`, `cert_delivery.py` и новый файл `guide_miniapp.py`:

- при успешной выдаче сертификата кнопка **«Инструкция»** появляется рядом с кнопками получения сертификата;
- кнопка также появляется при получении файлов сертификата;
- HTTPS-ссылка на готовый сайт открывается внутри Telegram как Mini App;
- если ссылка не задана, дополнительная кнопка не появляется.

**Изменения на компьютере ещё не обновляют работающего бота.** Нужно перенести эти четыре файла в существующий проект на сервере бота и перезапустить его обычным способом. Остальные файлы и настройки рабочего бота сохраняются. Способ загрузки и перезапуска зависит от того, где сейчас запущен бот.

В предоставленной локальной копии Glory-Bot отсутствует импортируемый файл `ui_buttons.py`, поэтому полный запуск этой копии пока невозможен. Для запуска нужен полный комплект файлов рабочего бота; создавать замену этому модулю наугад не нужно.

После обновления работающего бота:

1. Откройте бота как администратор.
2. Перейдите в **Настройки → Сертификаты API → Инструкция**. Нужный экран содержит строку **«Ссылка инструкции»**.
3. Отправьте HTTPS-адрес готовой страницы, например `https://ВАШ-ЛОГИН.github.io/glory-guide/guide/` со своим реальным логином и названием репозитория.
4. Дождитесь сообщения **«Ссылка на инструкцию сохранена»**.
5. Для уже существующего сертификата запросите файлы заново и проверьте кнопку. Старые сообщения Telegram сами не обновляются.
6. На iPhone нажмите **«Инструкция»** в личном чате с ботом. Проверьте открытие внутри Telegram, переходы по шагам, видео и возврат в чат. Новое сообщение успешной выдачи сертификата также должно содержать эту кнопку.

Ссылка вида `t.me/…` продолжит открываться как обычная Telegram-ссылка, а старый HTTP-адрес — как обычная ссылка. Для Mini App используйте именно опубликованный **HTTPS-адрес сайта**.

Настройка Mini App в BotFather сама по себе не добавляет кнопку к сообщению о готовом сертификате: это делает обновлённый код бота. Для описанной кнопки, работающей в личном чате пользователя с ботом, отдельная регистрация домена через `/setdomain` не требуется.

## 5. При желании добавьте постоянную кнопку меню

Это дополнительная кнопка рядом со строкой ввода сообщения; на кнопку в сообщении о сертификате она не влияет.

В [@BotFather](https://t.me/BotFather) отправьте `/setmenubutton`, выберите своего бота, укажите тот же HTTPS-адрес инструкции и текст **«Инструкция»**. После настройки проверьте меню в личном чате с ботом.

## 6. Как обновлять инструкцию

1. Внесите изменения в файлы Glory-Guide самостоятельно или через Codex.
2. В GitHub Desktop откройте репозиторий инструкции, напишите короткое описание изменений в **Summary** и нажмите **Commit to main**.
3. Нажмите **Push origin**.
4. Во вкладке **Actions** на GitHub дождитесь успешного завершения новой публикации.
5. Откройте инструкцию заново в Telegram и проверьте изменения.

Пока адрес сайта остаётся прежним, менять ссылку в настройках бота не нужно. Если переименуете репозиторий или смените домен, сначала проверьте новый адрес в Pages, затем сохраните его в боте.
